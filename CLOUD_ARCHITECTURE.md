- ============================================================
- TABLE: profiles
- ============================================================
- Mirrors user profile data from GDPR export
-
- CREATE TABLE profiles (
- id BIGINT PRIMARY KEY,
- user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
- name TEXT,
- avatar TEXT,
- banner_image TEXT,
- title_language VARCHAR(10),
- created_at TIMESTAMP DEFAULT NOW(),
- updated_at TIMESTAMP DEFAULT NOW()
- );
-
- RLS POLICY:
-   - Users can READ their own row
-   - Users can UPDATE their own row
-
- ============================================================
- TABLE: media_cache
- ============================================================
- AniList API cache (enrichment data)
- Shared across all users (not user-specific)
-
- CREATE TABLE media_cache (
- id BIGINT PRIMARY KEY,
- data JSONB,
- fetched_at TIMESTAMP DEFAULT NOW(),
- updated_at TIMESTAMP DEFAULT NOW()
- );
-
- RLS POLICY:
-   - Everyone can READ
-   - Only authenticated users can CREATE/UPDATE
-
- ============================================================
- TABLE: user_entries
- ============================================================
- User's anime/manga list entries (MOST CRITICAL FOR SYNC)
-
- CREATE TABLE user_entries (
- id BIGSERIAL PRIMARY KEY,
- user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
- entry_id BIGINT NOT NULL,
- series_id BIGINT NOT NULL,
- data JSONB NOT NULL,
- deleted BOOLEAN DEFAULT FALSE,
- deleted_at TIMESTAMP,
- edited_at TIMESTAMP DEFAULT NOW(),
- created_at TIMESTAMP DEFAULT NOW(),
- updated_at TIMESTAMP DEFAULT NOW(),
- UNIQUE(user_id, entry_id)
- );
-
- INDEXES:
-   - (user_id, deleted)
-   - (user_id, updated_at DESC) [for sync]
-   - (series_id) [for lookups]
-
- RLS POLICY:
-   - Users can READ/CREATE/UPDATE/DELETE only their own entries
-

- RLS POLICY:

- ROW LEVEL SECURITY (RLS) SETUP
- ============================================================

- All tables should have RLS ENABLED:
-
- ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
- ALTER TABLE user_entries ENABLE ROW LEVEL SECURITY;
- ALTER TABLE tier_boards ENABLE ROW LEVEL SECURITY;
- ALTER TABLE tiers ENABLE ROW LEVEL SECURITY;
- ALTER TABLE tier_assignments ENABLE ROW LEVEL SECURITY;
- ALTER TABLE tags ENABLE ROW LEVEL SECURITY;
- ALTER TABLE sync_queue ENABLE ROW LEVEL SECURITY;
- ALTER TABLE user_settings ENABLE ROW LEVEL SECURITY;
-
- ============================================================
- EXAMPLE RLS POLICY (user_entries table)
- ============================================================
-
- CREATE POLICY "Users can view own entries"
- ON user_entries FOR SELECT
- USING (auth.uid() = user_id);
-
- CREATE POLICY "Users can insert own entries"
- ON user_entries FOR INSERT
- WITH CHECK (auth.uid() = user_id);
-
- CREATE POLICY "Users can update own entries"
- ON user_entries FOR UPDATE
- USING (auth.uid() = user_id);
-
- CREATE POLICY "Users can delete own entries"
- ON user_entries FOR DELETE
- USING (auth.uid() = user_id);
-
- ============================================================
- CRITICAL SYNC CONSIDERATIONS
- ============================================================
-
-   1. CONFLICT RESOLUTION
-   - Last write wins (prefer `updated_at` timestamp)
-   - For offline edits: local takes priority, then sync to cloud
-
-   2. DELETED RECORDS
-   - Use soft deletes with `deleted` flag (for recovery)
-   - Never hard-delete until verified synced
-
-   3. TIMESTAMP FIELDS
-   - `created_at`: set once, never changes
-   - `updated_at`: changes on every modification
-   - `deleted_at`: when soft-deleted
-   - `synced_at`: when successfully synced to cloud
-
-   4. OFFLINE SUPPORT
-   - All operations happen locally first
-   - Sync queue collects changes
-   - Background job processes queue when online
-   - Manual "Sync Now" button available
